# semantic-system-map — Turn code graphs into explainable responsibilities

**Componente:** repository-intelligence

## Observable outcome

A user can explore an immutable repository snapshot through responsibility, dependency, deployable, interface, data, test and change-coupling lenses; every cluster and relation exposes evidence/provenance while uncovered, ambiguous and stale regions remain visible.

## Confirmed context

Raw AST graphs are too detailed to model work, and folders are not durable responsibilities. The map must derive useful aggregates without promoting them to accepted components. It consumes normalized snapshots from the built-in/Graphify adapters and must scale through bounded queries rather than loading an unfiltered graph into the browser.

## ▶ Handoff

Depend on readonly-analysis-runtime and at least one rich or fixture-backed normalized adapter. Build deterministic structural lenses first, then model-assisted responsibility hypotheses through planning-model-capabilities. Keep raw observed facts and inferred clusters separable. Coordinate a minimal evidence-first explorer with Client Experience; component acceptance remains Repository Planning territory.
