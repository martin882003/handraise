## Scope

Turn each connected Git repository into a trustworthy portfolio of components and executable fronts. Own adapter detection, native metadata formats, Director compatibility, component contracts, front plans and lifecycle rules, including assisted discovery and proposal of components during initialization.

## Limits

Does not own agent process execution, worktree mechanics, global device settings, authentication, or the visual design of portfolio screens. Director repositories may only be mutated through their validated helpers; compatibility must never bypass repository locks or lifecycle checks.

## Agent guidance

Model components as durable product responsibilities rather than folder mirrors. Keep Markdown human-readable, preserve unknown content when editing, validate cross-references, and make every native mutation atomic and serialized. For generated proposals, show repository evidence and uncertainty, make analysis read-only, and require explicit acceptance before writing definitions.

## Territory

`src/repositories.mjs`, `.handraise/project.json`, `.handraise/components/`, `.handraise/fronts/`, repository portfolio contracts, and their endpoints in `src/server.mjs`. The repository initialization and component/front screens are coordinated with Client Experience.
